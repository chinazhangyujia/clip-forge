# ClipForge desktop shell

This folder packages the FastAPI backend, the Next.js UI, and a static
ffmpeg/ffprobe pair into a single double-clickable desktop app via
[Tauri 2](https://tauri.app/). The shell is **purely** a wrapper —
no UI code lives here. The frontend stays in `web/` and the backend stays
in `backend/`; this folder just builds an installer that ships them
together so a non-technical user can install and run ClipForge without
setting up Python, Node, ffmpeg, or anything else.

## Layout

```
desktop/
├── README.md                      this file
├── .gitignore                     ignores build/, target/, fetched ffmpeg
├── scripts/
│   ├── build.sh                   end-to-end build pipeline
│   ├── fetch-ffmpeg.sh            downloads static ffmpeg/ffprobe
│   └── backend.spec               PyInstaller spec for the FastAPI sidecar
├── resources/
│   ├── mac/                       arm64 ffmpeg + ffprobe (gitignored)
│   └── win/                       x86_64 ffmpeg.exe + ffprobe.exe (gitignored)
├── build/                         build outputs (gitignored)
│   ├── icon-source.png            placeholder app icon
│   ├── backend-work/              PyInstaller intermediates
│   └── backend-dist/              PyInstaller output
└── src-tauri/                     Tauri Rust shell
    ├── Cargo.toml
    ├── tauri.conf.json
    ├── build.rs
    ├── icons/                     generated by `cargo tauri icon`
    ├── capabilities/default.json  IPC permissions
    ├── binaries/                  staged at build time, gitignored
    └── src/{main.rs,lib.rs}
```

## Runtime architecture

```
ClipForge.app                                (Tauri shell, ~10 MB)
└── spawns clipforge-backend (PyInstaller bundle, ~190 MB)
    ├── --port 0  → picks free localhost port, prints CLIPFORGE_PORT=<n>
    ├── --data-dir <user-chosen path>  (default: ~/Library/Application Support/com.clipforge.app/projects)
    └── --ffmpeg-dir <bundle resource>/binaries/ffmpeg

User config: ~/Library/Application Support/com.clipforge.app/config.json
```

The frontend (Next.js static export) runs inside the Tauri WebView and
asks the Rust shell for the backend URL via the `get_backend_url`
command (`web/src/lib/api.ts → initApi()`).

## Local build (macOS arm64)

Prerequisites:
- macOS 11+ on Apple Silicon
- Python 3.13 + [uv](https://github.com/astral-sh/uv)
- Node.js 20+
- Rust toolchain (`rustup install stable` → puts cargo in `~/.cargo/bin`)
- Tauri CLI: `cargo install tauri-cli --version "^2.0" --locked`

Then from the repo root:

```bash
export CLIPFORGE_DEEPSEEK_API_KEY="sk-..."
# optional:
export CLIPFORGE_ANTHROPIC_API_KEY="sk-ant-..."
export CLIPFORGE_LLM_PROVIDER="deepseek"   # or "claude"
export CLIPFORGE_WHISPER_MODEL="base"      # or "small" / "medium"

bash desktop/scripts/build.sh
```

Output:
- `desktop/src-tauri/target/release/bundle/macos/ClipForge.app` — drag to Applications
- `desktop/src-tauri/target/release/bundle/dmg/ClipForge_*.dmg` — distribute this

First Tauri build is slow (~10 min — compiles ~400 Rust crates). Subsequent
builds finish in ~1 min thanks to incremental compilation.

## CI build (both Mac and Windows)

`.github/workflows/build-desktop.yml` runs on every push to `main` and
produces both installers as artifacts. Configure:

1. Add `CLIPFORGE_DEEPSEEK_API_KEY` (and optionally
   `CLIPFORGE_ANTHROPIC_API_KEY`) under **Settings → Secrets and variables
   → Actions**.
2. Push to `main`. The workflow runs both `macos-latest` (arm64) and
   `windows-latest` (x86_64) jobs in parallel.
3. Download the installer from the workflow run's artifacts.

Tagging a release (`git tag v0.1.0 && git push --tags`) additionally
attaches the installers to a draft GitHub Release.

## Distributing to dogfood users

**macOS:** Hand them the `.dmg`. They drag to Applications, double-click.
First launch shows a Gatekeeper warning ("ClipForge cannot be opened
because Apple cannot check it for malicious software") because we're
not Apple-notarized — they right-click the app → **Open** → confirm.
After that, normal launches are silent.

**Windows:** Hand them the `.msi`. They run it through the standard
installer flow. First launch shows a SmartScreen warning ("Windows
protected your PC") because we don't have a code-signing certificate
— they click **More info** → **Run anyway**.

For wider distribution, get an Apple Developer membership ($99/yr) for
notarization and a Windows code-signing certificate ($200–500/yr).

## What's bundled vs. fetched at runtime

- **Whisper "base" model is bundled.** `scripts/fetch-whisper.sh` pre-downloads
  it into `desktop/build/whisper-base/` (~140 MB on disk, mostly `model.bin`),
  and the PyInstaller spec ships it inside the .app/.msi. The backend's
  `_resources.bundled_whisper_model_dir()` resolves to it at runtime, so the
  user's first transcribe is offline + instant. If `CLIPFORGE_WHISPER_MODEL`
  is changed to anything other than `base`, the backend falls back to the
  legacy lazy-download path (cached at `<workspace>/models/`).
- **No update channel.** Users redownload to upgrade. Adding
  [`tauri-plugin-updater`](https://docs.rs/tauri-plugin-updater/) is the
  next step once an auto-update feed is hosted.

## Known gotchas

- **Backend bundle is ~190 MB.** Driven by `faster-whisper` + `ctranslate2`
  + `tokenizers`. Hard to shrink without dropping Whisper.
- **API key leakage.** The DeepSeek key is baked into the Rust binary at
  compile time and is extractable with `strings`. Acceptable for trusted
  dogfooders; not for wider distribution.
- **Ffmpeg fetch is a build-time download.** No copy in git. If the
  upstream URL changes, update `scripts/fetch-ffmpeg.sh`.
- **Mac build is arm64 only.** For Intel Mac support, fetch x86_64
  builds from evermeet.cx and produce a universal binary with `lipo`.
- **Project directory picker UI is not yet wired in.** The shell
  exposes `pick_project_dir` and `get_project_dir` Tauri commands; the
  frontend doesn't currently call them. Default location is used unless
  the user edits `~/Library/Application Support/com.clipforge.app/config.json`
  manually. TODO: surface a Settings button in `TopNav.tsx`.
